# Application changelog

## 12 October 2026

- Keep the Octatrack beta publication check valid when release automation stamps the current commit and approval. Authored package contents and qualification fields remain pinned to the validated Git snapshot, and derived package hashes must match the published files.

- Fixed the host-side Windows package command by passing the qualified builder a relative JSON selector, and made temporary Git checkout cleanup handle read-only pack files. Nested Python builders also inherit UTF-8 for the catalogue’s text. Firmware inputs and published package bytes remain unchanged.

- Added the owner-approved, version-specific browser preservation guard for Tape Echo. It requires exact protected inputs and actual legacy-worker output equality; original evidence and hardware limitations remain unchanged. A missing or stale integration proof still blocks release. The binding also pins the checked-in two-snapshot runner; generation refuses mismatched or uncommitted inputs. The isolated publication test includes the preservation helper, so it still exercises the real release gates.

- The base-install guide shows one readable step at a time, keeps its next action visible, explains unsupported browsers, follows the Octatrack’s restart prompt and makes Connect Octatrack prominent only after the base download. “Help us find bugs” is a separate, dismissible diagnostics invitation for verified members, including regular users, with an explicit choice and clear data, retention and withdrawal details. Browser/build failure categories join the opt-in technical reports; the expanded scope requires fresh consent. USB syncing remains beta-only.

- Beta USB sync preflights loader capabilities and exact machine-package layouts, including retained Undo packages, before fetching or sending changes. Package identities, group membership and bounded record structure are checked before a transaction; unrecognised layouts and individual-machine migrations without exact rollback identity are refused. This prepares the browser for additional USB packages without publishing them or changing the qualified base.

- USB sync reviews now offer the base upgrade before fetching modules, show runtime package updates even when the module names stay the same, and return to the selected set after installation. A downloaded base remains pending until its exact IDENTIFY configuration digest reconnects; an older base or the download hash cannot confirm installation.
- Stopped applying card-firmware placement conflicts and swap prompts to the beta USB module-set library and module pages. Card checkout and classic views retain their exact baked checks; published USB package availability, ownership and the Octatrack’s on-demand DSP admission remain authoritative. Analog BD still needs its own USB port.

- Documentation: recorded private diagnostics consent v2, verified-member eligibility, closed browser/build failure fields, account isolation, retention, deletion and USB read constraints. Clarified the first base-install restart prompt; USB access remains beta-only.
- Empty beta module sets no longer show a green installed marker or “On your Octatrack” when the connected or remembered inventory is also empty. The sync row and sidebar keep the empty-set state separate from the device connection.
- The beta hub keeps Sync to Octatrack above the modules in a compact sticky row with the set name and add/remove counts. Long sets no longer push the primary action below the module grid; phones use a full-width button.
- Beta testers can opt into private Octatrack diagnostics from installation, the hub or account settings. Current consent is enforced by the server, expires after 90 days and can be withdrawn with deletion. Only documented technical fields are accepted; no firmware, samples, audio, project contents, set names, serial numbers or raw crash/memory dumps are collected. Records are retained for 30 days, capped per account, included in account export and visible only to their owner and site administrators. The later expanded member-wide choice described above now survives removal of beta access. Additional read-only status checks require opt-in, including after waiting for the USB interface. Collection and replies stay bound to the account that started them. Separate fixed daily sync-action totals honor existing count preferences and browser privacy signals.
- Beta base installation remembers a downloaded base in the current tab, shows “Waiting for your Octatrack”, and returns to the module set when a compatible base reconnects. Sync reviews lead with add/remove counts and tuck unchanged modules into a disclosure. Undo names the previous set when known; an acknowledged, saved Keep records the set and time in this browser, with disconnected inventory labelled “Last seen”.
- Missing-module notices in the beta hub separate the count, module names and next action. Add to set leads to the existing Sync to Octatrack review; modules absent from the library remain explicitly named.
- Editing or switching a beta Octatrack set keeps the page and USB connection open. The installation guide asks testers to stay connected and offers optional private diagnostics.
- Beta Octatrack module tiles keep their artwork at full colour before syncing and when removing a module. State labels and Keep/remove controls sit below the artwork so they no longer cover thumbnail text; touch controls have 44px targets. The existing base-install introduction uses “Sync to Octatrack”, and the development preview can start with an empty base for the first-install walkthrough. Public library views are unchanged.
- The beta sidebar prompts disconnected users to connect their Octatrack and original-OS users to install the base. Remembered modules are labelled “Last seen” rather than presented as currently connected.
- On narrow screens the beta hub keeps the Octatrack connection status and install button below its photo, preventing horizontal overflow.

- Made hardware feedback reminders and download follow-ups more compact, with module thumbnails, divided rows and side-by-side actions. Narrow panels keep full-sized touch controls, and reports retain the exact downloaded versions.
- Removed the New badges from Forum and Other projects in the sidebar and mobile menu.
- Made module-release announcements opt-in for each version. Deployments and media edits record release history quietly unless that version's authored notes explicitly set `announce: true`; existing subscriptions and delivery preferences remain intact.
- Limited FM Synth's Node and Python screenshot regressions to instrument captures so bundled audio previews are not decoded as PNGs or counted as screenshots; capture hashes and version/source checks remain required.
- Required the shared signal-art style for module thumbnails, documented the grid, palette and typography, and explained how to replace artwork whose original asset is bound by older release evidence.
- Documented explicit per-version announcement consent across the agent, module-author, publication and notification guides; publishing or editing media leaves announcements off by default.
- Documented focused comparisons and musical phrases without quiet padding, full Euclid clock/envelope capture, FM + Mini Verb capture through Octemu with offline VECTOR note generation, reliable parameter-lock editing, decoded MP3 checks and the retained-evidence editorial media path.

- Allow editorial documentation to be appended to a retained module's README when it also holds historical resource measurements. The entire approved record, other reports and runtime inputs remain immutable.
- Retained evidence compares exact approved infrastructure before consulting a historical builder-extension exception, so an obsolete exception cannot block an unchanged runtime.
- Documented how an authenticated Cloudflare operator can publish and verify an owner-approved site announcement when the admin UI is unavailable.
- Added slim waveform overlays for modules with audio previews: thumbnail-only hover and keyboard focus, click-to-seek playback, persistent controls while playing, and tap-to-play on mobile module pages. Existing card and thumbnail sizes are preserved.
- Verified members can upload public audio previews with credits and optional captions. The renamed Previews tab lists submitted recordings with usernames and captions; contributors and administrators can remove them. Uploads use the existing media bucket with file/request limits, retry protection and account-deletion cleanup. Synthetic recordings remain development-only.

- Prepared a fresh Discord invitation round with the existing announcement wording and link. Previous account and browser invitations no longer block this resend; each account or visitor browser receives the new round once. New signups still receive Discord inline in their welcome. Publication follows deployment through the admin announcement form.
- Bundled followed module releases into a daily digest, showing only the latest pending version and its changelog for each module. Replies and messages keep their chosen activity interval; existing follows, opt-outs and bell history are retained.

- Allowed up to 30 seconds for deployment release synchronization so a successful inventory fanout is not mistaken for a ten-second timeout. Existing idempotent retries, recipient preferences and digest processing remain in place.
- Fixed imported README provenance after adding audio previews, and limited E-Verb's monochrome capture checks to instrument screenshots.
- Documented imported-module media provenance updates and screenshot selection for mixed audio/image media.
- Local module README, TESTING and CPU guides can be edited without updating import checksums. Imported code, licences, archived snapshots and preserved upstream documentation retain exact integrity checks.
- Documentation PRs run a small Node-only import check so publication uses the same policy without requiring firmware builds or the full app suite. TapeHead's app checks share that policy.
- Added report triage: awaiting review, waiting for the reporter, investigating, confirmed bug and fix awaiting verification. Questions and suggestions are classified separately.
- Module warnings and quiet periods use confirmed bugs applicable to the current version or with unknown applicability. Unconfirmed reports remain visible; configuration reports do not blame individual modules.
- Maintainers can request information, classify, confirm, close and reopen reports through GitHub comments or consent-controlled report forms. Verified claimed maintainers can triage without release-author privileges. Existing author updates retain automatic CI-gated merge and publication.
- Added an insufficient-information closure outcome, retained closure explanations and kept older closed history without inferred outcomes. Retries and verified command acknowledgements avoid duplicate reporter notifications.
- Updated contributor prompts, GitHub report instructions and developer context. Firmware qualification, publication and verified-download resolution gates remain in force.
- Reworked module-card footers into one line: shorter testing grades, compact report counts with explanations and the Compare control.
